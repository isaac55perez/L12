# mail_assist MCP Server

This is an MCP server that exposes the features of the `gmail_extractor` to interact with your Gmail account.

## Setup and Run

1.  **Install Dependencies:**

    ```bash
    pip install -r requirements.txt
    ```

2.  **Run the Server:**

    ```bash
    cd gmail_extractor
    uvicorn main:app --reload
    ```

    The server will be running at `http://127.0.0.1:8000`.

## API Documentation

The API documentation is automatically generated by FastAPI and is available at:

*   **Swagger UI:** `http://127.0.0.1:8000/docs`
*   **ReDoc:** `http://127.0.0.1:8000/redoc`
*   **OpenAPI JSON:** `http://127.0.0.1:8000/openapi.json`

## Configuring Gemini and Claude

You can configure Gemini and Claude to use the `mail_assist` server as a tool by providing them with the OpenAPI specification.

### Gemini Configuration

To configure Gemini, you can use the `google.generativeai` library in Python. When you define your tool, you can point it to the `openapi.json` URL of your running server.

'''python
import google.generativeai as genai

# Configure the Gemini API key
genai.configure(api_key="YOUR_GEMINI_API_KEY")

# Define the tool from the OpenAPI spec
mail_assist_tool = genai.protos.Tool(
    function_declarations=[
        genai.protos.FunctionDeclaration(
            name="mail_assist",
            description="A tool to interact with your Gmail account.",
            parameters=genai.protos.Schema(
                type=genai.protos.Type.OBJECT,
                properties={
                    "openapi_spec": genai.protos.Schema(
                        type=genai.protos.Type.STRING,
                        description="The URL to the openapi.json spec.",
                    )
                },
                required=["openapi_spec"],
            ),
        )
    ]
)

# In your chat session, you would then pass the tool and the URL
# This is a conceptual example. The actual implementation might vary based on the Gemini API version.
# Refer to the official Gemini documentation for the latest on tool configuration.
'''

### Claude Configuration

For Claude, you would typically define the tool in the JSON format that the Anthropic API expects. You would need to manually translate the OpenAPI specification into this format.

Here is a conceptual example of how you might define one of the tools for Claude:

'''json
{
  "name": "get_recent_emails",
  "description": "Get recent emails from the last N days.",
  "input_schema": {
    "type": "object",
    "properties": {
      "days": {
        "type": "integer",
        "description": "Number of days to look back for recent emails.",
        "default": 7
      },
      "max_results": {
        "type": "integer",
        "description": "Maximum number of emails to return.",
        "default": 10
      }
    }
  }
}
'''

You would then make this tool available to your Claude model. When the model decides to use the tool, your application code would be responsible for calling the `mail_assist` server's endpoint (`/tools/get_recent_emails`) with the parameters provided by the model.

### Using the `/prompt` Endpoint

Both Gemini and Claude can also interact with the `/prompt` endpoint. You can define a simple tool that takes a string query and sends it to the `/prompt` endpoint.

**Tool Definition:**

'''json
{
  "name": "gmail_prompt",
  "description": "Ask a question about your Gmail in natural language.",
  "input_schema": {
    "type": "object",
    "properties": {
      "query": {
        "type": "string",
        "description": "Your question in natural language (e.g., 'get my recent emails')."
      }
    },
    "required": ["query"]
  }
}
'''

Your application would then call the `POST /prompt` endpoint with the user's query.

This provides a flexible way to interact with the `mail_assist` server without needing to expose all the individual tools directly to the LLM.
